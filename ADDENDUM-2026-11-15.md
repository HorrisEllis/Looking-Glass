# Looking Glass — ADDENDUM 2026-11-15

SPEC.md (v0.3) and PHASEMAP.md are kept exactly as they were. This addendum records what has been decided since, so nothing is lost.
The decisions are James's; the reading of them is the coder's, said where it is.

## His words

- 2026-11-15: "looking glass for the ui editor, builder, etc. this is to replace electron, build applications for emerge code."
- 2026-11-05: "I want to replace electron with this. Emerge rebuild the canvas." · Looking Glass's core: all Emerge · "I'm building
  bottom up. Emerge needs to get finished to the point of being able to have you code with it. I am trying to reduce as much friction."
- 2026-11-15 (Glass Engine notes): "like making a ui editor, that can edit electron, html, etc. should be mapped to phase."
- Earlier (his stated goal for the editor): a full, enterprise-grade, agnostic UI editor that makes beautiful animated UI with particles
  and variable / event-driven styles; code generated deterministically from the UI elements, like WordPress page editing — not by AI.

## What changes against SPEC.md and PHASEMAP.md

| | SPEC / PHASEMAP v0.3 | Now |
|---|---|---|
| Purpose | A UI renderer and app host | Also **the UI editor and app builder** for applications written in Emerge, and the replacement for Electron in his systems (ERAVOS, COS, Clear Glass, Idearium) |
| Language | Rust / Zig / C++ for one static exe; `crates/` in the layout | **All Emerge** (decided 2026-11-05). `crates/lg-*` read as `lg/<module>/` in Emerge; the layout rule is the Nexus one: a folder per module, a file per component, core at the root |
| Order | Phase 0 → 12, editor in Phase 11 | Emerge first (E1 native_lang F5 · E2 native_windows · E3 calling Windows: imports, Win64 calls, memory, callbacks · E4 the "only kernel32" axiom, his call), then **LG1**: one borderless window drawing one rectangle from data (software, then GPU), then the phases as mapped |
| Editor | Self-hosted, edits the live scene tree | The same, and **edits other UIs too**: Electron/HTML apps as an import path (read their DOM/CSS into typed UI data), so his existing apps can move over one surface at a time |
| Code | — | Deterministic: the editor writes Emerge (and, while Electron remains, HTML) from the UI data. No AI in the generation path |

## Phases added (proposed, to confirm)

- **LG-B1 Builder: an app from data.** A Looking Glass app = a scene file + its Emerge logic + a manifest; `eg build` produces one
  executable (PHASEMAP Phase 12's packaging, reached through Emerge's native target). Depends on Phase 8 (host, app model) and E2.
  Exit test: a two-screen app made in the editor builds to one exe and runs on a clean Windows machine.
- **LG-I1 Import an Electron/HTML surface.** Read a page's DOM and computed styles into UI data (elements, variables, layers); what
  cannot be read is listed, not guessed. Depends on Phase 2. Exit test: one ERAVOS tool face imported, then drawn by Looking Glass
  beside the original, compared by pixels.
- **LG-E0 The editor moves earlier (question).** PHASEMAP keeps the editor at Phase 11 on purpose ("after a working scene, bus, and
  runtime"). Building UI in it sooner reduces friction; building it before the bus exists risks redoing it. Read here: keep it at 11,
  but let LG-I1 and a read-only inspector come early. His call.
